# Update Rules

Use discovery when planning and integration when drafting authorized
changes. For maintenance, apply these rules within the requested scope.

## Discovery Before Approval

Find the existing source note for the same source. Before proposing a new
concept note, search existing names, aliases, and content for the same or
closely related meaning. After the user selects content, derive proposed
note boundaries from that selection and show them in the final plan.
Resolve paths before edit approval; do not bundle note placement with
keep/omit questions. Use the clearest standard concept name. Do not rename
an existing note just to normalize it.

## Integration After Approval

The approved plan governs changes to an existing note, not all knowledge
the note may retain. Preserve existing knowledge unless its removal or
replacement is part of the approved treatment. Merge additions into the
existing structure and preserve useful user wording. Leave unchanged
content alone.

A conflicting claim from a new source is not automatically a correction.
Preserve relevant conditions and attribution when they explain the
difference; otherwise raise the conflict before replacing existing claims.

### Source Notes

Update the matching source note. Add a compact entry for newly processed
scope; revise the matching entry when reprocessing the same scope instead
of duplicating it. Revise earlier entries when approved work corrects or
clarifies the source's contribution.

### Concept Notes

Update a matching note when the source contributes a correction, clearer
reasoning, a better example, useful nuance, or a meaningful source
reference. Avoid duplicate explanations and references. When an approved
rename or removal affects links, repair those links as part of the change.
