# Question Guide

Use this guide after reading the requested scope and before writing
notes. Questions discover user preference only where several useful
treatments remain.

## Analyze The Source

Identify:

- the source's knowledge contribution
- the reasoning that makes the contribution understandable
- meaningful content and its role
- possible boundaries between concept notes

Useful content roles include:

- central knowledge
- supporting knowledge
- enabling principle or mechanism
- example
- artifact
- necessary context

Present each meaningful item once.

## Present The Checkpoint

Every note-generation run includes a compact checkpoint.

### Inferred Logic

Show the source's useful reasoning as a short sequence or compact
explanation.

### Inventory And Treatment Map

Map each meaningful item to a proposed treatment and reason. Use a
table, short list, or another concise form suited to the scope.

Treatments may include:

- create or update an individual concept note
- merge into an existing concept note
- integrate as supporting knowledge
- keep only in the source note
- preserve, simplify, generalize, replace, compress, or omit source
  material
- represent knowledge through prose, bullets, a table, a diagram, or
  another suitable form

Account for each enabling principle or mechanism. Name or link it in
the central note, give it an individual concept note, or keep it in the
source note according to the agreed treatment.

### Proposed Note Flow

Show how the note will develop the knowledge. Indicate where supporting
knowledge, examples, and artifacts will carry the explanation. Treat
this flow as a settled drafting plan derived from the source.

### Settled Decisions

State only the rule-settled decisions that materially affect the
current scope. These may include note location, integration of an
example, treatment of an image, or required source and log updates.

### Preference Decisions

Ask numbered questions only when multiple useful treatments remain.
Distinguish essential mechanisms from supporting concepts with
independent review value and from context needed only by an example.

Give enough context to show how each option would affect future review.
Group closely related choices when that makes the decision clearer.

When the user's preferences are already known or the user requests best
judgment, state the settled choices and return to `workflow-rules.md`
for edit approval.
